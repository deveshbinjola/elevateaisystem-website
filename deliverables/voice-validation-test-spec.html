Onboarding Feature Spec · v1

The voice validation test. Prove the spine works before they pay.

Steve's insight from the demo: voice is the spine. If a coach can't feel themselves in the output, none of the leads, content, or carousels matter. This is the moment of truth, built into onboarding, that decides whether the platform is real for them.

Why this exists

Voice is either there or it isn't. Make them feel it on day one.

Coaches have been burned by AI tools that sound generic. They sign up, generate a post, recognize none of themselves in it, and quietly stop using the product. The voice validation test removes that drift by forcing the moment of recognition into the first session, when they still have energy to engage.

"The language wasn't perfect yet. The carousels are good but the voice still sounds a bit AI. If you can prove the voice works in the first 5 minutes, everything else lands. If you can't, nothing else matters." Steve, demo session, 2026-05-07

Prevents silent churn

Coaches who never trust the voice quietly stop logging in. By surfacing voice match in onboarding, we replace silent attrition with a visible decision the user makes consciously.

Sharpens the voice profile

The user's score is training signal. A 2 means the voice profile missed; we re-run extraction with their flagged words. A 5 means we locked in. Either way, the system gets sharper.

Sets the bar for paid conversion

If voice scores below threshold, we don't pitch the upgrade. We loop them back through Instagram import or the questionnaire. Trust first, payment second.

Becomes the demo wedge

"Take 3 minutes. Rewrite a generic paragraph in your voice. If it doesn't sound like you, you don't pay." That's the line that closes pilots, not features.

The Flow

Four steps. Three to five minutes. One decision.

Runs after voice extraction (Instagram import or questionnaire) and before content generation unlocks. The user can't generate posts until they pass or explicitly choose to retry voice training.

01

Show the original

3 generic paragraphs about a topic in their niche. Visibly bland on purpose. Labeled "Generic version."

02

Show the rewrite

Same 3 paragraphs, rewritten in their voice using the extracted profile. Labeled "Your version." Side by side with the original on desktop, stacked on mobile.

03

They score it

Single 1 to 5 slider per paragraph. Plain question: "Does this sound like you?" Plus an optional "what's off" text field per paragraph.

04

System decides

Average score ≥ 4 unlocks the platform. 3 to 3.9 triggers a single re-train pass. Below 3 sends them back to questionnaire with their flagged words pre-loaded.

What the user sees

Side by side. No marketing copy. No spin.

The contrast does the work. If the rewrite has signal, the user feels it before they finish reading. If the rewrite is generic, they catch it on the first sentence.

Generic version

Many coaches struggle with finding consistent leads in today's competitive market. The good news is that with the right systems and AI tools, you can build a sustainable pipeline that brings in qualified prospects every single week. Let's explore how to set this up properly.

Your version

Most coaches don't have a lead problem. They have a system problem. The leads were always there. The pipeline was just leaking. Fix the leak. Build the rails. The leads come.

The right side has rhythm, voice, sentence-length variation, and an opinion. The left side has none of those. The user scores honestly because the difference is felt, not argued.

Scoring + thresholds

Average across 3 paragraphs. The system acts on the number.

No human in the loop on the threshold. The user scores, the system routes. This keeps the experience fast and removes any sense that we're grading their honesty.

Build spec

What ships in the first cut.

Scoped for a single sprint. Voice extraction already exists; this feature is the layer on top that surfaces and validates it.

01

Generic paragraph library

Curated set of bland baseline paragraphs across 5 niches: men's coaching, business coaching, fitness, mindset, creator economy.

  • 15 paragraphs minimum (3 per niche)
  • Stored as JSON in Supabase, niche-tagged
  • Random selection of 3 at test time, 1 per niche if user flagged multi
02

Voice rewrite endpoint

Single API call that takes generic paragraph + voice profile and returns rewrite. Reuses the existing content generation prompt with a "rewrite this faithfully in their voice" instruction.

  • Claude API, ~3 to 5 second response
  • Deterministic temperature (0.3) for consistency
  • Token budget: 800 in, 800 out per paragraph
03

Side-by-side UI

Two-column layout on desktop, stacked on mobile. Each paragraph row has its own slider and optional text field.

  • Slider with discrete stops at 1, 2, 3, 4, 5
  • Mid-slider label: "Sounds like me"
  • "What's off" field: 200 char max, optional
04

Routing engine

On submit, compute average. Match against thresholds. Route the user without an intermediate page.

  • Pass: navigate to dashboard with onboarding complete flag
  • Re-train: regenerate with flagged words inserted into prompt
  • Fail: send back to voice import step with progress preserved
05

Telemetry

Every test attempt logged. We need this data to tune the voice profile pipeline over time.

  • cp_voice_test_attempts table in Supabase
  • Fields: user_id, attempt_n, scores[], flagged_words[], outcome, ts
  • Dashboard cell on Sunny's command view: % first-attempt pass
06

Re-train logic

If avg lands in 3.0 to 3.9, take the user's "what's off" text and inject it into the rewrite prompt as negative examples ("avoid: X, Y, Z").

  • Hard cap of 1 re-train pass before falling back to voice import
  • Re-train counts toward attempt_n in telemetry
  • Show progress: "Tuning voice... ~10 seconds"
Acceptance criteria

Six things must be true before this ships to the pilot.

If any of these miss, hold the release. The whole point of this feature is trust. A buggy version causes the exact problem it's meant to solve.

✓

3 paragraphs render in under 8 seconds total on a fresh session. If the user waits more than 10 seconds for output they will close the tab.

✓

The rewrite uses the actual voice profile, not a mocked output. Test with 3 known voice profiles and confirm three distinctly different rewrites of the same generic paragraph.

✓

Re-train cycle works end to end. User flags "too corporate" on a paragraph, system re-runs, second rewrite measurably less corporate (verified in QA pass with 5 sample profiles).

✓

No em-dashes in any generated output. The rewrite prompt explicitly bans them. QA must grep all 15 baseline-paragraph rewrites and confirm zero em-dashes shipped.

✓

Telemetry writes correctly to cp_voice_test_attempts. Manually verified by triggering 5 test runs and reading the table. Dashboard cell on command view reflects the data within 60 seconds.

✓

Mobile layout works on a 390px viewport. Stacked paragraphs, full-width sliders, no horizontal scroll. Tested on real iOS Safari, not just Chrome devtools.
